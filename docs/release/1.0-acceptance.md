# SourceSlate 1.0 Acceptance Gate

A release candidate is eligible for `v1.0.0` only when the repository-controlled gates are implemented **and** every external validation gate has been observed passing.

Status used below:

- `[x]` — implemented and covered by repository code/tests/workflow configuration.
- `[ ]` — still requires execution or external validation before the release tag is created.

Repository coverage is not a substitute for an observed green CI/release run.

## Installation and packaging

- [x] Composer metadata is configured for `phpwalter/sourceslate`, including the `sourceslate` binary.
- [x] `composer validate --strict` is part of CI/release validation.
- [x] PHP 8.3 and PHP 8.4 are part of the CI matrix.
- [x] Composer archive generation is part of the release workflow.
- [x] The release workflow verifies that a `vX.Y.Z` tag matches `SourceSlate\Version::VERSION`.
- [ ] Verify `composer global require phpwalter/sourceslate` from a clean machine after the package is published/available through Packagist.
- [ ] Verify the globally installed `sourceslate --version` reports `1.0.0`.

## Release decision

Do **not** create the `v1.0.0` tag merely because repository implementation is complete. Tag only after:

1. the final integration commit has a fully green Linux/Windows/macOS CI matrix;
2. the final documentation/site smoke review is complete;
3. external HTTPS/SSH credential-path tests are complete;
4. Packagist/global-install readiness is confirmed; and
5. no release-blocking defects remain.

This separation keeps SourceSlate's 1.0 gate evidence-based: repository tests prove what they can prove, and external systems are not marked complete until they have actually been exercised.
